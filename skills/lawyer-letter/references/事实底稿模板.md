# 事实底稿模板 — 发函前 G1 门禁强制产物

> **来源**：某科技公司项目 `[日期]_事实底稿_[事项]，四节结构实战验证有效。
> **定位**：G1 事实核验的产出物。未完成本底稿 = G1 门禁未过 = 不得起草正文（P0 红线 1）。
> **存放**：`02_scratch/事实底稿/[日期]_事实底稿_[事项]_v01_同步稿.md`

---

```markdown
# [日期]_事实底稿_[事项]_v01_同步稿

## 一、已核对事实

1. 发函主体：[律所全称——以执业许可证登记名称为准]；委托人：[全称]；收函对象：[全称——以企查查/天眼查最新工商登记为准，已核验存续状态：存续/更名/注销]。**收件人身份核验：姓名/名称经[系统/网站]核验一致，身份信息已保存 PDF 打印归档**（上海指引第 10 条）。
2. 合同名称及编号：《[名称]》，编号：[XX]，签署日期：[日期]。
3. [关键条款摘录：付款/验收/违约条款——必须与合同原文逐字核对，前提性表述不得省略]
4. [履行事实：验收/交付/付款记录，含证据载体]
5. [金额事实：总额、已付、未付，勾稽关系]
6. [违约条款有无：明示「现有合同未见针对 XX 的固定违约金或滞纳金标准」（如适用）]
7. 引用法条：《民法典》第 XX 条、第 XX 条已通过[全国人大法律法规数据库/北大法宝/元典]核验，现行有效。
8. 诉讼时效：债务到期日 [日期]，时效届满日 [日期]，[未逾时效/临近时效——临近的须先经指导律师评估出函策略]。
9. 合同通知送达条款：[有约定——地址/方式/视为送达条款摘录；无约定——按注册地址+实际经营地双地址寄送]。
10. 付款前提成就状态及证据归属方（有前提条件的合同必填）：前提为「[条款摘录]」；成就状态 [已成就在我方可证（证据：XX）/ 成就证据在对方侧，我方无法独立核实——函件口径为要求对方限期书面说明]。
11. **事实审查六要素**（上海指引第 10 条 + XX市/厦门指引，逐项回答）：①主张要求名称准确、范围明晰、内容固定——[是/否，说明] ②委托人对其主张切实拥有合法权利——[依据] ③第三方与委托人关系——[关系性质] ④第三方是否存在违约/侵权及具体事实——[事实+证据] ⑤第三方可能承担的法律责任——[责任类型] ⑥证据材料能否支持律师意见——[是/部分/否，缺口]。
12. **关键事实交叉核对记录**：合同编号/金额/日期/主体名称/验收状态各经 ≥2 来源核对——[来源 1 vs 来源 2，一致/不一致的处理]。
13. **谈话笔录（仅委托人陈述、无客观证据的案件强制）**：[已制作，编号/日期/签字盖章情况 / 不适用——客观证据充分]。

## 二、委托人陈述或待补充核验事实

1. [委托人声称但无独立证据的事项，注明来源为委托人陈述，后续应归档原始材料]
2. [待补充材料清单：发票 PDF/流水/签收记录等]
3. [函件中需要保留的口径：如「保留对方限期说明 XX 情况的口径」]

## 三、本轮文书同步口径

1. 本轮以 `[基础稿文件名]` 为基础，不回退至旧稿。
2. 新生成稿：`[新稿文件名]`。
3. 文书中保留委托人标黄确认点：[逐项列出]。
4. 文书修正重点：[本稿相对上稿的关键改动及理由]。

## 四、轻量裁判视角核验

1. [检索路径记录：成功的记录来源，失败的记录断点（如「北大法宝返回 HTTP 524，未取得有效结果，仅作失败断点记录」）]
2. [类案 1-3 条：案号 + 与本案相似点 + 裁判要旨]
3. 裁判视角结论：[本函口径稳健性判断——如「要求限期验收+支付+说明情况整体稳健；对未到期款项采用条件成就口径比直接认定全部立即到期更稳」]
```

## 填写规则

| 规则 | 说明 |
|------|------|
| 二分强制 | 「已核对」与「委托人陈述/待核验」严格分开，没证据的只是声称 |
| 逐字核对 | 合同条款引用必须与原文一致，前提性表述（如「里程碑签收后付款」）不得省略 |
| 法条核验 | 写明核验渠道；记忆引用的法条必须重新核验 |
| 检索断点 | 工具失败记录断点并切换路径，不得跳过裁判视角核验 |
| 标黄确认点 | 委托人确认稿中的标黄项逐项登记，定稿前逐点核销 |
